# sbi0：Sv39 恒等映射 + PSRAM

日期：2026-08-29  
对照：rCore-Tutorial-v3 第 4 章（Sv39、恒等映射）  
板子：Sipeed M1s Dock / BL808 D0（C906）  
分支 / worktree：实现时用 `sbi0-sv39` @ `.worktrees/sv39`

## 目标

在已跑通时钟的 `sbi0` 上：M 态初始化 PSRAM 并冒烟，S 态建 Sv39 恒等页表、开 `satp`，之后仍能 `ecall` 打印，并能读写 PSRAM。

ACM0（`2000000 8N1`）必须按这个顺序出现，每行 `\r\n`：

```text
rust helloworld from D0/C906, uart up
rust helloworld from D0/C906, ipc synced
rust helloworld from D0/C906, icache on
[M] psram ok
[M] sbi0 entering S-mode
[S] hello via sbi
[S] satp on
[S] psram ok
[M] shutdown
```

缺任何一行、或顺序不对，就算失败。`[S] satp on` 和后面的 `[S] psram ok` 必须发生在 `satp.MODE=Sv39` 之后。

## 非目标

- 不把 rCore 拷进仓库，不上 RustSBI / OpenSBI。
- 不改 helloworld / stage0。
- 不改细粒度 PMP（仍全开）。
- 不要求 5 次 tick（第 3 章已过）。时钟 SBI 和 `trap_s` 可留着，但 `s_main` 不再开 `SIE` / 打 tick。
- 不做 `sfence.vma` SBI 扩展、ASID、非恒等映射、U 态。
- shutdown 仍是打字后空转。

## 结构

继续改 crate `sbi0/`，产物仍是 `sbi0.bin` @ Flash `0x100000`。不新建 crate。

HAL 优先：`bouffalo_hal::psram::init_psram(&p.psram, &p.glb)`。TZC 放行 HAL 没有，对照 C `Tzc_Sec_PSRAMA_Access_Release` 手搓。页表、`satp` 用 `riscv`。

## PSRAM 硬件

窗口：`0x50000000`，64MB（手册 / Linux `low_load`）。控制器：`p.psram` @ `0x3000F000`。

M 态在 I-cache、mtimer、trap、`mcounteren.TM` 之后、`mret` 之前：

1. `init_psram`（HAL：拉 `ldo12uhs`，写 PHY 魔数）。C SDK 完整路径还有 UHS PLL + `Psram_UHS_x16_Init_Override`；先用 HAL。冒烟失败再补 C 缺口，不要一上来抄整份校准。
2. TZC：`TZC_SEC_BASE = 0x20005000`，`TZC_PSRAMA_TZSRG_CTRL` 偏移 `0x380`。对照 `Tzc_Sec_PSRAMA_Access_Release`：清 region0 的 EN 位（bit 16）。
3. 冒烟：在 `0x50001000` 写 `0x5A5A_5A5A_5A5A_5A5A`，读回相同则打 `[M] psram ok`。失败打 `[M] psram fail` 后空转，不要进 S 态。

页表占用 `0x50000000` 起 4KiB，不要拿这块做冒烟。

## Sv39 映射

C906 Sv39。恒等映射，两条 **1GB 叶**（根页表 level-2）：

| 根 PTE 下标 | VA/PA 起点 | 盖住 |
|-------------|------------|------|
| 0 | `0x00000000` | VRAM 栈 `0x3f00_0000`、MM 外设 |
| 1 | `0x40000000` | PSRAM `0x50000000`、XIP `0x58000000` |

根页表：`0x50000000`，4KiB 对齐，512 个 `u64` 先清零。

PTE：`(ppn << 10) | 0xC7`。`0xC7` = V|R|W|X|A|D。C906 不置 A/D 容易 page fault。`U=0`、`G=0`。1GB 叶的 PPN 按 4KiB 页号：`phys >> 12`（`0x0` → `0`，`0x40000000` → `0x40000`）。

`satp`：`MODE=Sv39`（8），ASID=0，PPN=`0x50000000 >> 12`。用 `riscv::register::satp::set`。写前、写后都 `sfence.vma`（`riscv::asm::sfence_vma_all`）。写页表后、开 satp 前：对根页表 4KiB 做 `dcache_cpa`/`dcache_cpal1`（C906 用 l1 变体）再 fence。不要调 HAL `l1c_dcache_clean_range`（地址过滤不可靠）。

## M 态相对现 sbi0 的改动

1. `main` 在 `enter_s_mode` 之前：init PSRAM、TZC、冒烟。
2. `s_main` 不再跑 tick 循环。`trap_m` / `a7=0` set_timer 可保留。
3. 开 satp 之后的 page fault 仍进 M（`medeleg=0`）。`[M] trap` 继续打印 `mcause` 十六进制。

## S 态

`s_main`（仍只走 putchar / shutdown `ecall`）：

1. `[S] hello via sbi`（此时 `satp=0`，证明 SBI 未坏）。
2. 在 `0x50000000` 建根页表（两条 1GB 叶）。
3. 清 D-cache + `sfence.vma`，写 `satp`，再 `sfence.vma`。
4. `[S] satp on`。
5. 再写读 `0x50001000`（图案 `0xA5A5_A5A5_A5A5_A5A5`，与 M 态冒烟不同，证明开页表后的访问）。成功打 `[S] psram ok`，否则 `[S] psram fail` 后 shutdown。
6. `sbi_shutdown`。

S 态禁止写 UART FIFO。不要为了映射去碰 `0x30002000`。

## 失败怎么看

| 现象 | 含义 |
|------|------|
| 无 `[M] psram ok`，有 `[M] psram fail` | HAL init 不够（UHS PLL / PHY）或 TZC 没放行 |
| `[M] psram ok` 之后沉默 / `[M] trap` | 进 S 或 hello 之前就炸了，与页表无关 |
| 有 hello，无 `[S] satp on` | 建表或写 `satp` 时取指/存页表 fault（`mcause` 12/13/15） |
| 有 `[S] satp on`，无 `[S] psram ok` | 映射没盖住 `0x50001000`，或开 satp 后 PSRAM 访问失败 |
| `[S] trap` | S 态收到了非预期中断（不该开 `SIE`） |
