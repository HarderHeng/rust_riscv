# sbi0：Sv39 + PSRAM

日期：2026-08-29  
对照：rCore-Tutorial-v3 第 4 章（Sv39）  
板子：Sipeed M1s Dock / BL808 D0（C906）  
分支 / worktree：`sbi0-sv39` @ `.worktrees/sv39`  
状态：**2026-08-29 板上已打出** `[S] satp on` / `[S] psram ok` / `[M] shutdown`

初稿按「两条 1GB 恒等叶 + 低 VA 取指」写。实机上数据恒等能过，**S 取指必须走 Linux `PAGE_OFFSET` 高 VA**。落地以 `docs/architecture.md`「C906 Sv39」为准，下面保留目标日志和失败对照。

## 目标

在已跑通时钟的 `sbi0` 上：M 态初始化 PSRAM 并冒烟，S 态建 Sv39、开 `satp`，之后仍能 `ecall` 打印，并能读写 PSRAM。S **取指**走 Linux `PAGE_OFFSET` 高 VA，不是低地址恒等。

ACM0（`2000000 8N1`）必须按这个顺序出现，每行 `\r\n`：

```text
rust helloworld from D0/C906, uart up
rust helloworld from D0/C906, ipc synced
rust helloworld from D0/C906, icache on
[M] psram ok
[M] sbi0 entering S-mode
[S] hello via sbi
[S] satp on
[S] psram ok
[M] shutdown
```

缺任何一行、或顺序不对，就算失败。`[S] satp on` 和后面的 `[S] psram ok` 必须发生在 `satp.MODE=Sv39` 之后。

## 非目标

- 不把 rCore 拷进仓库，不上 RustSBI / OpenSBI。
- 不改 helloworld / stage0。
- 不改细粒度 PMP（仍全开）。
- 不要求 5 次 tick（第 3 章已过）。时钟 SBI 和 `trap_s` 可留着，但 `s_main` 不再开 `SIE` / 打 tick。
- 不做 `sfence.vma` SBI 扩展、ASID、U 态。S 取指必须是高 VA（非恒等）；PSRAM 探测可以恒等 data。
- shutdown 仍是打字后空转。

## 结构

继续改 crate `sbi0/`，产物仍是 `sbi0.bin` @ Flash `0x100000`。不新建 crate。

HAL 优先：`bouffalo_hal::psram::init_psram(&p.psram, &p.glb)`。TZC 放行 HAL 没有，对照 C `Tzc_Sec_PSRAMA_Access_Release` 手搓。页表、`satp` 用 `riscv`。

## PSRAM 硬件

窗口：`0x50000000`，64MB（手册 / Linux `low_load`）。控制器：`p.psram` @ `0x3000F000`。

M 态在 I-cache、mtimer、trap、`mcounteren.TM` 之后、`mret` 之前：

1. `init_psram`（HAL：拉 `ldo12uhs`，写 PHY 魔数）。**这一期只做 HAL + TZC**，不上 UHS PLL / `Psram_UHS_x16_Init_Override`。冒烟失败就停在 `[M] psram fail`，另开一轮再补 C 缺口。
2. TZC：`TZC_SEC_BASE = 0x20005000`，`TZC_PSRAMA_TZSRG_CTRL` 偏移 `0x380`。对照 `Tzc_Sec_PSRAMA_Access_Release`：清 region0 的 EN 位（bit 16）。
3. 冒烟：在 `0x50001000` 写 `0x5A5A_5A5A_5A5A_5A5A`，读回相同则打 `[M] psram ok`。失败打 `[M] psram fail` 后空转，不要进 S 态。

页表占用 `0x50004000` 起（根 / L1 / L0），trampoline `0x50002000`。冒烟仍用 `0x50001000`。

## Sv39 映射

C906 Sv39。对照本机 Linux `head.S` `relocate`，**不要**再走低 VA 恒等取指（1GB / 2MB / 4K 都试过，数据 PTW 能过、S I-fetch 必 cause 12）。

| VA | PA | 叶 | 用途 |
|----|----|----|------|
| `0xffffffe000000000` | `0x50000000` | 2MB `PAGE_KERNEL_EXEC`（`0x70000000140000ef`） | 开 `satp` 后的 S 取指 |
| `0x50000000` | `0x50000000` | 2MB `PAGE_KERNEL`（无 X） | S 态 `lui` 探测 |
| （物理，satp=0） | `0x50002000` | — | trampoline：`csrw satp` |

根：`0x50004000`。`root[vpn2(PAGE_OFFSET)=0x180]` → L1 `0x50005000`，`L1[0]` 是 2MB 叶。非叶只置 V（`PAGE_TABLE`）。可执行叶：Linux `PAGE_KERNEL_EXEC` = V|R|W|X|G|A|D|SH|B|C。缺 MAEE 或叶上 C/B 时开 `satp` 会 `mcause=0`（指令地址非对齐），不是 12。进 S 前用 `xuantie_riscv::register::mxstatus` 置 `THEADISAEE`、`MM`、`MAEE`，清 MHRD。

`satp`：`MODE=Sv39`（8），ASID=0，PPN=`0x50004000 >> 12`。S 在 trampoline 里 `csrw satp`。写页表后：对表页按 64 字节步进 `xuantie_riscv::asm::dcache_cpal1`，再 `fence`。不要用 `dcache_cpa`，不要调 HAL `l1c_dcache_clean_range`。

`enter_s_mode` 仍先把 `satp` 写成 0 再 `mret`。开分页只发生在 `s_main` 打完 hello 之后。`s_main` **禁止**开 `sie.STIE` / `sstatus.SIE`。`csrw satp` 后下一条物理取指会 IPF；M 把 `mepc` 改到 `PAGE_OFFSET+0x2004`（`medeleg` 仍为 0）。

## M 态相对现 sbi0 的改动

1. `main` 在 `enter_s_mode` 之前：init PSRAM、TZC、冒烟。
2. `s_main` 不再跑 tick 循环。`trap_m` / `a7=0` set_timer 可保留。
3. 开 satp 之后的 page fault 仍进 M（`medeleg=0`）。trampoline 上的指令页错误（`mepc == 0x50002004`）改 `mepc` 到高 VA，不要当普通 `[M] trap` 打完就停。其它 `[M] trap` 继续打印 `mcause` 十六进制。

## S 态

`s_main`（仍只走 putchar / shutdown `ecall`）：

1. `[S] hello via sbi`（此时 `satp=0`，证明 SBI 未坏）。
2. 建 `PAGE_OFFSET` → PSRAM 2MB 可执行叶 + PSRAM 恒等 data 叶；把 trampoline 拷到 `0x50002000`。
3. 跳到 trampoline：`csrw satp`。下一条物理取指 IPF，M 改 `mepc` 到高 VA。
4. `[S] satp on`（必须发生在高 VA 上）。
5. 再写读 `0x50001000`（图案 `0xA5A5_A5A5_A5A5_A5A5`）。成功打 `[S] psram ok`，否则 `[S] psram fail` 后 shutdown。
6. `sbi_shutdown`。

S 态禁止写 UART FIFO。不要为了映射去碰 `0x30002000`。

## 失败怎么看

| 现象 | 含义 |
|------|------|
| 无 `[M] psram ok`，有 `[M] psram fail` | HAL init 不够（UHS PLL / PHY）或 TZC 没放行 |
| `[M] psram ok` 之后沉默 / `[M] trap` | 进 S 或 hello 之前就炸了，与页表无关 |
| 有 hello，无 `[S] satp on`，`mcause=12` 且 `mepc` 是低 VA | 低 VA 恒等取指；应走 trampoline + M 改 `mepc` 到 `PAGE_OFFSET` |
| 写 `satp` 后 `mcause=0` | 缺 MAEE 或可执行叶缺 C/B |
| `[M] ipf->kva` 之后仍无 `[S] satp on` | 高 VA 叶没盖住 trampoline，或 `mepc` 改错 |
| 有 `[S] satp on`，无 `[S] psram ok` | 映射没盖住 `0x50001000`，或开 satp 后 PSRAM 访问失败 |
| `[S] trap` | S 态收到了非预期中断（不该开 `SIE`） |
