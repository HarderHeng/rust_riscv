# sbi0：最小 SBI（putchar + shutdown）

日期：2026-08-29  
对照：rCore-Tutorial-v3 第 2 章（S 态经 SBI 控制台 / 关机）  
板子：Sipeed M1s Dock / BL808 D0（C906）  
分支 / worktree：`sbi0` @ `.worktrees/sbi0`

## 目标

证明 S 态能通过 `ecall` 进 M 态，由 M 态代写 UART3。这是接 rCore / 完整 SBI 的前置，本身不是内核，也不是 RustSBI。

ACM0（`2000000 8N1`）上必须按这个顺序出现，每行以 `\r\n` 结尾：

```text
rust helloworld from D0/C906, uart up
rust helloworld from D0/C906, ipc synced
rust helloworld from D0/C906, icache on
[M] sbi0 entering S-mode
[S] hello via sbi
[M] shutdown
```

`[S] hello via sbi` 只能由 S 态对每个字节发 `ecall`（`a7=1`）打出。  
`[M] shutdown` 只能由 M 态处理 `a7=8` 时打出。  
S 态不得再写 `0x30002000+0x88`。看不到这两行就算失败。

## 非目标

- 不上 OpenSBI / RustSBI crate，不实现现代 SBI（`a6` 功能号、`a0/a1` 错误对）。
- 不做 `sbi_set_timer`、`sbi_console_getchar`、IPI、RFENCE。
- 不启页表（`satp` 保持 0），不配 S 态中断，不启 PSRAM。
- 不改细粒度 PMP（继续 `pmpaddr0=-1`，`pmpcfg0=0x1F`）。
- 不加 rCore-Tutorial submodule，不改 helloworld 两个 crate。
- `sbi_shutdown` 不做真断电 / 芯片复位；打完 `[M] shutdown` 后空转，避免和“核死了”分不清。

## 结构

| 产物 | 角色 | Flash |
|------|------|--------|
| `helloworld-m0.bin` | 已验证的 M0 拉核（不改） | `0x0` |
| `sbi0.bin` | 新 crate：M 态初始化 + `mtvec` + 旧版 SBI + S 态 `ecall` | `0x100000` |
| `stage0.bin` | 对照：S 态直接写 FIFO | `0x100000`（仅对照时） |
| `helloworld-d0.bin` | 对照：双核 M 态循环 | `0x100000`（仅对照时） |

新 crate：`sbi0/`，`bl808-dsp`，依赖与 `stage0` 相同（workspace git HAL）。  
`scripts/build.sh` 额外产出 `target/riscv64imac-unknown-none-elf/release/sbi0.bin`，并打印烧 `helloworld-m0` + `sbi0` 的命令。  
默认 S 态路径改烧 `sbi0.bin`。stage0 继续编译，不删。

M 态前缀（时钟、IPC、I-cache、PMP、FIFO `putb`）从 `stage0/src/main.rs` 抄过来，这一期不抽公共 crate。

## M 态

与 stage0 相同的前半，不要发明第二套拉核/时钟：

1. `enable_uart3_clock`（XCLK 40 MHz）。
2. GPIO16/17 + `uart3.freerun(..., Uart3Xclk)`，2 Mbps。
3. 打印 `uart up`（`write!(..., "...\r\n")`）。
4. `wait_for_m0`，然后打印 `ipc synced`。
5. `enable_icache`，然后打印 `icache on`。
6. `pmp_allow_all`（同 stage0）。
7. 覆盖 `bouffalo-rt` 的 `mtvec`：写成 `trap_m`，direct 模式（低 2 位 = 0）。
8. `medeleg = 0`，`mideleg = 0`。关 `mie` / `sie`。
9. 打印 `[M] sbi0 entering S-mode` 并 `flush`。
10. `satp = 0`，`mstatus.MPP = S`，`mepc = s_main`，`mret`。

UART 行尾一律 `\r\n`。不要用只加 `\n` 的 `writeln!`。

## 陷阱与旧版 SBI

S 态 `ecall` 的 `mcause` 是 **9**（Environment call from S-mode）。不委托，全部进 M 态。

调用约定对齐 rCore-Tutorial-v3 第 2 章旧 SBI（`a7` 就是功能号，不用 `a6`）：

| `a7` | 名字 | 行为 | 返回 `a0` |
|------|------|------|-----------|
| `1` | `sbi_console_putchar` | 把 `a0` 低 8 位写入 UART3 FIFO（同 stage0：等 `UART_FIFO_CONFIG_1[5:0] != 0` 再写 `+0x88`） | `0` |
| `8` | `sbi_shutdown` | 用 FIFO 打出 `[M] shutdown\r\n`，然后 `loop { spin_loop() }`，不再 `mret` | 不返回 |

其它 `a7`：FIFO 打出 `[M] bad sbi\r\n`，空转。  
其它 `mcause`（含中断）：FIFO 打出 `[M] trap\r\n`，空转。

只有 `a7=1`（putchar）处理完后：`mepc += 4`，`mret` 回 S 态，`a0=0`。`mstatus.MPP` 保持 S。  
`a7=8`、未知 `a7`、以及非 9 的 `mcause` 都在 M 态空转，不 `mret`。

陷阱帧：保存除 `x0` 外全部 GPR（实现上比少存更稳）。不换独立 trap 栈（单 hart、无中断）。`asm!` 不要用 rustc 1.93 会拒的 `out` + `options(noreturn)` 组合；需要不返回时用 `unreachable_unchecked()`，和 stage0 的 `mret` 一样。

只有 M 态写 UART3 FIFO。陷阱路径不调用 HAL。

## S 态

`s_main`（`-> !`）：

- 复用当前 `sp`，不换栈，不调 HAL。
- 对 `"[S] hello via sbi\r\n"` 的每个字节：`a0 = byte`，`a1 = 0`，`a2 = 0`，`a7 = 1`，`ecall`。
- 然后 `a7 = 8`，`ecall`（不应返回）。
- 若误返回：空转。

## 失败怎么看

| 现象 | 含义 |
|------|------|
| 完全没字 | 镜像 hash / 没进下载模式 / 烧错地址（先烧 stage0 或 helloworld-d0） |
| 只有 `uart up` | IPC，M0 没起来或 cache 没 clean |
| 有 `[M] sbi0 entering S-mode` 没有 `[S]` | `mret`、`mtvec`、PMP，或 S 态 `ecall` 没进处理函数 |
| 有 `[S]` 没有 `[M] shutdown` | `a7=8` 没被识别，或 shutdown 路径没打字 |
| `[M] trap` | 不是 S 态 `ecall`（`mcause≠9`），或中断进来了 |
| `[M] bad sbi` | `a7` 不是 1 或 8 |
| `[S]` 乱码 | 时钟/波特率；M 态那几行若正常则更像 FIFO 等待条件写反 |
